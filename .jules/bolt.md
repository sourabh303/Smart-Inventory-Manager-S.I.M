## 2024-05-24 - Missing Caching on Stats Endpoint\n**Learning:** The `/api/stats` endpoint makes multiple separate COUNT queries to the database on every request without caching. Given that stats are likely polled frequently by the dashboard, this is inefficient.\n**Action:** Combine the multiple COUNT queries into a single query and consider adding a small in-memory cache or returning a slightly stale result to reduce database load if needed. However, since the database is SQLite, a single query with conditional aggregation is a great first step.
